# 设计取舍记录

记下已经做过的判断和理由。改之前先读完，确认新方案真的更好，再改这里。

## 2026-10-25 检索不用向量库，用内存倒排索引

语料 144 条、正文约 15 万字，建索引不到一秒。向量库要额外服务、额外依赖，收益在这个规模上看不出来。
切词用汉字二元组加拉丁词，不引分词库。

**代价**：不懂同义改写，「美国大选」这类库外问题可能靠词面重合混进几条。由提示词规则拒答兜底。
**如果重来**：先补文献摘要，再考虑 bge-m3 这类本地小模型做混合检索。

## 2026-10-25 SQLite 从 JSON 派生，每次启动重建

`data/*.json` 是唯一真值，`backend/knowledge.db` 只是运行时产物，已 gitignore。
改数据不需要迁移脚本，重启即可；部署也不需要持久盘。

## 2026-10-25 检索门槛：覆盖率 0.25、相对分 0.25、长句最低 40

三个数都是实测调出来的，不是理论值。目的只有一个：宁可返回「没有」，也不给凑数的出处。
0.34 太严，会把「迁都」这类只命中主题词的条目挡掉；0.25 兼顾召回。

改门槛必须重跑 `backend/test_offline.py` 与 `smoke_test.py`。

## 2026-10-25 首条来源给 3600 字正文，其余 1200 字

案例正文普遍三五千字。只给 1400 字时，模型读不到后半段的评估结果，会回答「材料没有相关数据」。
第一条给足，显著改善回答质量，代价是提示词变长。

## 2026-10-25 来源由后端返回，不让模型拼链接

模型只负责作答和标注 `[n]`。来源列表是结构化数据，模型改不了出处，前端也不会渲染出假链接。
系统提示词里写死：只依据材料、资料不足就直说、不得推测题录类文献的内容、涉及数量只用给定统计。

## 2026-10-26 限流放进程内存

单实例、免费套餐，内存计数够用。重启清零，多实例不共享。
要更严就换 Redis，当前规模不值得。

## 2026-10-27 前端只维护 `backend/static/`

根目录 `index.html` 是离线入口，由 `scripts/build.py` 生成，冻结。
两套前端并存必然分叉，UI 改动一律去 `backend/static/`。

## 2026-10-27 文献在页面里读 PDF，不渲染提取文本

PDF 原貌最可靠。提取文本会混入公式碎片、页眉页码、两栏错位，直接展示阅读体验差。
提取结果只用于检索与问答，页面通过 `/api/papers/{cat}/pdf` 渲染 PDF。

阅读器用 **PDF.js**（`backend/static/vendor/pdfjs/`，3.11.174），不用 iframe 加浏览器插件。
原因：浏览器把 PDF 设为「总是下载」时 iframe 是空白；无头浏览器、移动端也不一致。
PDF.js 逐页渲染到 canvas，翻页与缩放自己控制，行为可预期。代价是仓库多 1.4MB 静态文件。

canvas 按 2 倍超采样再缩回显示，否则普通屏幕上文字发虚。缩放档位 75%—300%，100% 为适配宽度。

前端脚本设 `Cache-Control: no-cache`：发版后浏览器缓存旧 `app.js` 会继续跑旧逻辑，曾导致页面一直显示空白 iframe，必须手动强刷才恢复。

**代价**：PDF 必须在服务器上。课程资料 650MB 未入库，线上部署读不到。

## 2026-10-27 PDF 收进仓库 papers_pdf/

R2 需要订阅与绑卡，用户不走这条路。改为把被引用的 97 篇 PDF 平铺成
`papers_pdf/{cat}.pdf` 提交进公开仓库（225.8MB），Render 部署时随代码一起拉取，
后端优先读这个目录。

**代价**：仓库变大；公开仓库等于公开分发付费论文；推送 225MB 在弱网下容易中断。
**保留的后路**：R2 的代码路径与上传脚本仍在，配 `PDF_BASE_URL` 与清单即可切回。

## 2026-10-27 PDF 走对象存储时的 307 设计

仓库不存 PDF：650MB 且含付费论文与学生作业，提交进公开仓库既臃肿又有版权问题。
上传脚本把文件放到 `papers/{cat}.pdf`，生成 `pdf_manifest.json` 入库；服务端据此把
`/api/papers/{cat}/pdf` 307 到 R2。本地没有 R2 时退回读磁盘，两种模式同一套代码。

307 而不是代理：R2 原生支持 Range，浏览器阅读器可以直接拖进度条，不必经 Python 中转。

## 2026-10-27 文献只索引前 15k 字

96 篇全文合计 1030 万字。全量入内存倒排会占几百 MB，Render 免费实例只有 512MB。
只索引每篇前 15k 字，实测索引内存 55MB、建索引 0.1 秒。题名、摘要、引言足以定位主题。

## 2026-10-27 绝对分门槛只对中文查询生效

中文走二元组，命中面宽、容易凑分，需要用绝对分挡掉离题问题；
英文是整词匹配，正文权重为 1，绝对分天然偏小，同一门槛会误杀合法查询。
因此 `MIN_TOP_LONG` 与 20 分门槛只在中文字符出现时启用。

## 2026-10-27 案例作者暂不匿名，保留脚本

44 个案例是往届学生所写，23 个署名。是否公开姓名需经任课老师同意。
脱敏脚本已备好：`scripts/anonymize_authors.py`，默认只输出到 `cases.anon.json`，不覆盖原文件。
